# 2026.320.1554 — feat(clawsweeper-review)!: add the Arch package set so the candy can build on CachyOS

## Summary

Adds the **Arch package set** to the candy's `distro:` map, so an image composing it on CachyOS/Arch
installs its dependencies instead of none.

The candy declared only `ubuntu:`. Its own install is distro-agnostic — Node arrives as the upstream
`nodejs.org` tarball, pnpm and codex come from npm — so only the *package namespace* differs. This is a
translation of the same dependency set, not a second install path:

| package | why |
|---|---|
| `git`, `curl`, `ca-certificates` | the engine checkout and the Node tarball fetch |
| `xz` | `tar -xJf` on that tarball — measured on the Ubuntu box as `tar (child): xz: Cannot exec` |
| `jq` | the engine's profile / verdict plumbing |
| `python` | the engine's Python pieces |
| `bubblewrap` | Codex's read-only review sandbox |
| `icu`, `openssl` | Node 24's shared-library deps |

**Why now:** `clawsweeper-review` is being re-homed from an Ubuntu image to a **CachyOS pod**
(opencharly/opencharly#1068, operator decision D-3). That is impossible while the only distro section is
Ubuntu's — the CachyOS image would build and then fail at runtime for missing libraries.

**Names verified, not assumed.** Each resolved in the pac repos on the CachyOS-family base image this
org builds: `extra git`, `core curl`, `core ca-certificates`, `core xz`, `extra jq`, `core python`,
`extra bubblewrap`, `core icu`, `core openssl`.

**RCA for the skip:** `check-codex-runtime` is declared `context: [runtime]` — it inspects a RUNNING
deployment's writable home — and `charly check box` evaluates build-context checks against the image, so
a runtime-scoped step is correctly out of scope there. It is not skipped for a missing credential and it
is not a silent pass: the consumer's bed (`check-clawsweeper-review-pod` in `distro-cachyos`) deploys the
image, and that bed is where this step executes.

**The proof harness, and what DISP means here:** the box was a **candy-only image definition — it
declares no `vm:`, no `pod:` and no deploy of any kind**, so no deployment target was created, marked
disposable, or destroyed. `charly check box` runs its checks in a throwaway container of the built image.
There was therefore no autonomous destroy/rebuild to mark `disposable: true`: the only thing removed was
a temporary local candy copy and the box YAML that referenced it, both uncommitted working-tree files.

The diff is the candy and nothing else. `git status` was clean before the commit and is clean now.

dependencies, which is the state before this change.
