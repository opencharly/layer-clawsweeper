# 2026.296.0624 — feat(clawsweeper-review): the review engine as a pinned charly candy

## Summary

The ClawSweeper review engine as a charly candy: a pinned upstream checkout, Node 24 + pnpm
12.4.1, the OpenAI Codex CLI (the engine's only runner) on the OpenCharly Ollama Cloud
`responses` endpoint, a generic `opencharly` target-profile fallback, and a one-shot
`--local-range` entrypoint that prints the verdict as JSON.

This is the producer for the advisory review lane. It deliberately carries **no** GitHub App,
webhook, Cloudflare Worker, queue or state repo: the review reads the PR tree mounted read-only
and is given no token, so it can run on the self-hosted fleet as a disposable container.

## Why this shape

- **Pins, not `latest`.** `CLAWSWEEPER_COMMIT`, `NODE_VERSION`, `PNPM_VERSION`, `CODEX_VERSION`
  are `var:`s, advanced producer-first.
- **The model path is measured.** Codex accepts only `wire_api = "responses"`; Ollama Cloud
  serves stateless Responses at `https://ollama.com/v1`. A probe ran a real shell tool call:
  `codex exec` executed `uname -s && uname -m` and returned `Linux` / `x86_64`, then
  `tokens used`. The candy writes exactly that configuration and asserts its two lines.
- **The profile is an overlay.** ClawSweeper refuses a repository it has no profile for; the
  candy appends an owner-wide `opencharly` fallback, so any `opencharly/<repo>` resolves and an
  upstream sync never conflicts with a local config edit. The candy asserts the entry.
- **No token can leak.** `--local-range` performs no GitHub reads or writes; the container gets
  the tree read-only and only `OLLAMA_API_KEY`.
- **Codex loads `$CODEX_HOME/config.toml`** — the exact filename, not a lookalike; the build check
  names that path, and the entrypoint exercises its own flag surface via `--help`.

## How tested

Build-time checks are the gate the image carries into every consumer:

```yaml
check-node        node --version            -> v24.*
check-pnpm        pnpm --version           -> 12.4.1
check-check       codex --version          -> 0.162.1
check-engine      node dist/clawsweeper.js --help
check-profile     jq -e '.generic_fallbacks[] | select(.owner == "opencharly")'
check-codex-config base_url + wire_api lines
check-entrypoint  /usr/local/bin/clawsweeper-review exec bit
```

The live end-to-end proof lands with the consumer: a box + disposable bed in
`opencharly/distro-ubuntu` that runs a real review against a fixture and asserts a JSON verdict
(or skips visibly when `OLLAMA_API_KEY` is absent, R8), then the reusable workflow in
`opencharly/.github` and a caller in `opencharly/crabbox`.
