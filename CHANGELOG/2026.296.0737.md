# 2026.296.0737 — fix(clawsweeper-review): make the three advertised tools actually true in the image

## Summary

The candy's own ADE checks were red on the built image, and `charly box build` never runs them — so the
image shipped advertising three things it did not do. Measured on
`ghcr.io/opencharly/clawsweeper-review:check-clawsweeper-review-pod-2026.296.0731` (4 passed, 3 failed):

- **`check-pnpm` — reported 12.15.0 and DOWNLOADED it at run time.** Corepack answers with its own
  known-good version whenever it runs outside a tree that declares `packageManager`, so the "pinned
  12.4.1" claim was false everywhere but `/opt/clawsweeper`, and every call needed the network. pnpm now
  comes from npm at `PNPM_VERSION`: version-stable wherever it runs, no download.
- **`check-codex` — `codex: command not found`**, while `/opt/node/bin/codex` existed. npm's global bin
  lives in the Node tree, which is not on PATH, and only `node npm npx corepack` were linked. `pnpm` and
  `codex` are linked now.
- **`check-engine` — the engine refused to start**: `generic_fallbacks[2].allow_repo_name_pattern must be
  a string`. The opencharly target-profile overlay omitted it; added, identical to the two upstream
  entries. The check itself was ALSO false: the engine has no `--help` path (`--help`, `review --help`
  and no-args all print the same "Hosted review requires …" error and exit non-zero), so
  `node dist/clawsweeper.js --help` could never pass. It now imports the built profile module — the exact
  thing that threw — and asserts an opencharly repo resolves to `packageManager: npm`.

Also, and outside the diff: the repository's **default branch was still `chore/bootstrap`** (the seed), so
a plain clone of the repo got the seed tree, not this candy. Set to `main`.
