# 2026.296.0843 — feat(clawsweeper-review): bake the engine's input scanner into the image

## Summary

The engine refuses every review with

```
Agent input scan refused: scanner_unavailable. Restore trusted scan prerequisites or remove
sensitive input before retrying.
```

when it cannot resolve its input scanner, which is **TruffleHog**, bootstrapped by upstream's
`scripts/setup-review-tools.mjs`. That bootstrap downloads on demand, so an image that never installs it
depends on egress at REVIEW time and fails closed when that path is unavailable — measured on the runner
(`crabbox#16`): the review ran, fetched the PR, built its context, then refused its own input.

The candy now pre-installs the scanner at build time **as the image user**, into that user's own cache,
so a review never downloads anything.

## Round 2 findings — both closed by making the check inspect the artifact

**1. "The check invokes the downloader."** Correct: calling `setup-review-tools.mjs` makes the check pass
whether or not the image baked anything. It no longer calls it. It inspects the cache the build was
supposed to produce, so an un-baked image fails:

```bash
root="${HOME}/.clawsweeper-review-tools"
test -d "$root"
scanner="$(find "$root" -type f -name trufflehog -perm -u+x | head -1)"
test -n "$scanner"; test -x "$scanner"
```

**2. "`${USER}` is unverified."** The check now pins the identity instead of trusting the transcript:
it refuses to run as root, and it requires the calling user to own both `$HOME` and the cache root:

```bash
echo "check user: $(id -un) uid=$(id -u) home=${HOME}"
test "$(id -u)" -ne 0
test "$(id -un)" = "$(stat -c %U "$HOME")"
test "$(id -un)" = "$(stat -c %U "$root")"
test "$(stat -c %a "$root")" = "700"
```

If `run_as: "${USER}"` ever resolved to the build process's root user, `id -u` would be 0 and the build
fails — so the bake cannot silently land in `/root`.
