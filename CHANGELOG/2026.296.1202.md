# 2026.296.1202 — fix(skill): the skill node's description is the FILE's, not a second copy

## Summary

Head `dcf1a48c53bb0e8ecdb920170ccb932f931539a2`, **1 file, +5 −4** — the `clawsweeper-review` candy's
skill node no longer carries an inline `description:`, so the skill's body file is the single
source of record for the published prose.

**The defect.** `candy/clawsweeper-review/charly.yml` carried a `skill:` node with an inline
`description:` that disagreed with `.agents/skills/clawsweeper-review/SKILL.md`'s frontmatter. The
corpus generator treats that as a HARD ERROR — two sources of truth for one published page is the
ambiguity the relocation of skill bodies to files exists to remove — so the whole corpus cannot be
generated while it stands.

**What it breaks, measured.** The marketplace's own refresh (opencharly/marketplace, run
39947024902) exits 1 on exactly this:

```
charly marketplace: skill "clawsweeper-review": the node's inline `description:` and its file's frontmatter disagree
```

The corpus is the input the umbrella's `layer-charly-internals` guidance is vendored through, so
while this stands the corpus cannot be regenerated at any pin — and the producer-first chain that
carries the umbrella's git-workflow mechanics (layer-charly-internals -> marketplace -> docs ->
the umbrella's gitlink) is blocked at its second link.

**The fix, at the root.** The inline `description:` is deleted. `plugin-marketplace`'s
`fillSkillFromFile` takes the FILE's frontmatter when the node declares none
(`s.Description = sf.Description`) and refuses only when the two disagree — so the file becomes
the single source of record, and the published prose is the file's text, which is what the corpus
would have published had the two agreed. Nothing else in this repo changes.
