# 2026.296.0854 — feat(clawsweeper-review): forward extra engine options from the entrypoint

## Summary

The image ships the full ClawSweeper engine, but the entrypoint fixed the entire invocation, so a caller
could not reach capabilities the image already contains. The entrypoint now forwards extra engine
options.

The ones that matter for an advisory PR review:

- **`--body-file`** — the engine reviews THAT exact body and assesses its proof claims against it
  (`AUTHORITATIVE PR BODY … Do NOT fetch, prefer, or assume any other version`). Without it a review
  cannot see what the PR says it did, which is most of what a reviewer must judge.
- **`--output-retention debug`** — keeps round-over-round history: *"the next debug run receives the
  previous findings and dispositions so it can verify fixes and avoid re-raising resolved findings."*
  Selectable through `OUTPUT_RETENTION` (default `summary`, unchanged).
- **`--additional-policy`**, **`--verbose`**, and whatever the engine grows next.

The image still decides the MODE (`--local-range`, the only mode that needs no GitHub token) and the
output FORMAT (`--result-format json`). The caller refines; it cannot switch to a mode that would need
credentials the container does not have.

## Why not the other modes

The engine also documents a planner, an apply lane, a repair lane, `--local-only` item review,
`--preflight`, a review cache, advisory labels and a triage dashboard. Those need a GitHub token with
write scope or a durable state store. This image runs with **no token and no socket** by design, so they
are deliberately out of reach here — the advisory review is the part that can be done safely.
