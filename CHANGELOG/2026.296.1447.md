# 2026.296.1447 — fix(clawsweeper-review): raise the review's reasoning effort from low to medium

## Summary

`model_reasoning_effort` for the review goes from `"low"` to `"medium"`.

The review's last act is emitting a rigid JSON decision, and at `low` that is exactly where it
breaks. The failure is **not** hidden at the engine: an engine failure still exits 1 and still
reddens the advisory check. This changes the model side of the failure only.

## The measurement

On `opencharly/crabbox#17`, head `522aad6`, on the image built from this tree:

```console
[review] 13:24:33Z shard=0/1 start-comment=skipped #0
[review] 13:30:55Z decision-repair-turn #0 failed
[review] 13:30:55Z shard=0/1 done #0 decision=keep_open confidence=low action=kept_open
codex-failure classification=content_or_output
##[error]clawsweeper-review exited 1; the redacted output is posted as the comment.
```

Seven minutes of work produced a decision and a 9,742-character report, then the
`decision-repair-turn` could not repair the structured output. The same run self-reported
`confidence=low` — which is what `reasoning_effort = "low"` predicts for a task whose entire
output contract is a strict JSON object.

This is the same class as the earlier `invalid structured output` failure filed as
`opencharly/clawsweeper#3`.

## Why not the engine

I offered the alternative — treating "exited 1 but produced a report" as advisory success — and
it was **declined**: the engine's failure stays visible. So the knob changed is the one the
measurement points at, not the one that would make the symptom disappear.
