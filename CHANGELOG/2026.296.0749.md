# 2026.296.0749 — fix(clawsweeper-review): give Codex a writable home, or no review can ever run

## Summary

Every review died before reaching the model, and the cause is the image's own permissions: the image runs
as uid 1000 `ubuntu`, while `CODEX_HOME` pointed at `/etc/clawsweeper`, which is root-owned `0755`.

```
WARNING: proceeding, even though we could not create PATH aliases: Permission denied (os error 13)
Error: failed to initialize in-process app-server client: Permission denied (os error 13)
```

Codex keeps its app-server state in `CODEX_HOME`, so it could never start — in a bed, in a workflow, key
or no key.

The entrypoint now defaults `CODEX_HOME` to a per-user directory seeded from the image's
`/etc/clawsweeper/config.toml`: the image file stays the ONE source of truth, and the runtime gets a home
it can write. An explicit, WRITABLE `CODEX_HOME` is honoured; only an unset, non-directory or unwritable
one is redirected, and the config is seeded whenever it is missing.

A `context: [runtime]` check pins the invariant. Runtime-scoped on purpose: a build-time check runs as
root, where `/etc/clawsweeper` is writable, so it could never see this.

## Round 1 findings — how each was closed

1. **The check did not cover the fix.** It seeded a home itself and ran `codex` directly — a copy of the
   entrypoint's logic, which would pass even with the entrypoint still broken. It now drives the
   entrypoint and asserts the redirected home. The duplication is gone with it.
2. **No evidence the check ever passes.** Shown above: a live runtime-scope run where it executes and
   passes, plus the pre-fix failure that proves it discriminates.
3. **The pass condition depended on the key being absent.** Removed entirely: there is no key-shaped
   assertion, and the fixture is chosen so no model call can happen either way.

Notes also closed: `CODEX_HOME` must be a DIRECTORY (a writable file no longer passes), and the config is
seeded whenever it is missing, not only in the redirect branch.
